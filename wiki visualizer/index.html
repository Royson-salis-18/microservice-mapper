03 The Engineering Progression: "First We Did This, Then We Did This"

Understanding the architecture as a logical chronological progression from raw target discovery to automated root-cause intelligence:

Step 1 • Infrastructure & Connection Layer
Zero-Touch SSH Discovery & Docker Compose Parsing

First: We connect to the target EC2 instance via SSH (21-connection-layer.html). The system scans the remote filesystem, locates docker-compose.yml, and extracts the declared microservice architecture without installing any agent packages beforehand.

Step 2 • Data Plane & Daemon Runtime
Deploy Remote Collector & Extract Host Telemetry

Then: We spin up the lightweight remote-collector daemon (07-remote-collector.html). It hooks into /var/run/docker.sock for live CPU/memory stats, demuxes the Docker 8-byte log framing to stream HTTP access logs, and reads /proc/net/tcp to detect live ESTABLISHED socket connections.

Step 3 • Ingestion Pipeline & Canonical GraphStore
Ingest Telemetry, Normalize Canonical IDs & Prune Ghosts

Next: The telemetry envelope streams back via reverse SSH tunnel to the central server (05-telemetry-ingestion.html). The GraphStore executes normalizeId() (04-id-system.html) to eliminate ghost duplicates, merges declared vs observed dependencies, and buffers metrics in circular ring buffers.

Step 4 • Real-Time Frontend & 3D Visualization
Stream Live Graph State to 2D (XYFlow) & 3D (Three.js) UI

After That: The server broadcasts updates over WebSockets (10-websocket.html). The React 19 client (09-frontend.html, 24-client-frontend.html) renders interactive 2D graphs and a Three.js 3D spatial view, animating live packet pulses across active edges.

Step 5 • Intelligence, RCA & Risk Scoring
Compute Blast Radius & Trace Root Cause Cascades via BFS

Then: When performance drops, the RiskEngine (22-risk-engine.html) computes vulnerability blast radius, and the RCAEngine (08-rca-engine.html) evaluates 4-factor scoring across anomalous services, performing BFS propagation to isolate the root cause.

Step 6 • Traffic Generation & Python ML Sidecar
Automate Traffic Sweeps & Train Unsupervised Anomaly Detectors

Finally: The TrafficController (20-traffic-experiments.html) sweeps endpoints to generate synthetic load, while the Python ML sidecar (11-ml-pipeline.html, 26-ml-pipeline-deep-dive.html) fits IsolationForest models on baseline metrics to uncover subtle metric drift.
